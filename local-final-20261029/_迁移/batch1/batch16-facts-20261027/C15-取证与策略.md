## 三、面板与可达性

- **ReturnUI（1018）**：活动面板（HomeActiveUI）点 toggle 1018 → `ReturnModel.reqGetReturnSevenDayData()`（scripts2:28808-28814）→ 回包 eRet==1 → `CHANGE_ACTIVE_PAGE{prefabName:"ReturnUI"}`（28970-28977）→ `prefabs.load("activeUI/ReturnUI")`（29214）。
- **活动列表来源**：HomeActiveToggle 的 toggle 由服务端活动配置驱动（同 C11/C12 面板系）。1018 是否出现在列表里取决于我们回的 active 数据 —— 面板可达性**待真机确认**（不影响 keys 实现，回包正确时打开链路已通）。
- **新春 NewYear23**：addComponent 名单（29218-29219）在活动面板内；`GET_SPRING_SEVEN_DAY_DATA` 回包驱动的面板打开点**未找到**（W2 未确认）；新春风 3 键的触发是 start() 自动拉（55141）。
- **CheckItem 弹窗**：全部按钮驱动，非回包分支 → 无崩点风险。

## 四、★档位方案（供拍板）

### 档 A（推荐：可玩最小闭环 + 诚实空态 + 防刷合规）
- **做 6（回归系）**：
  1. `GET_RETURN_SEVEN_DAY_DATA`：**门 + 七日状态**（常开：triggerTime=now，回归期=const360 天）
  2. `RETURN_SEVEN_DAYS_AWARDS`：领当日（按天推进，**每天一次** → 计时循环有每日上限，符合上游新规）
  3. `GET_RETURN_TASK_DATA`：任务列表（state 全 0 = 展示不可领；**不伪造完成**）
  4. `RECEIVE_RETURN_DAILY_TASK`：拒绝（任务恒未完成 → eRet 2；诚实，防止白拿）
  5. `RECEIVE_LIVENESS_AWARD`：拒绝（liveness 恒 0；诚实）
  6. `GET_RETURN_GIFT` + `REFRESH_RETURN_GIFT_AWARD`：礼包**纯展示**（giftDatas 全 isBuy=0/isAward=0；giftAwards=[]）；`RECEIVE_RETURN_GIFT_AWARD` **拒绝**（未付费防白拿）
- **不做 3（挂 ISSUE-15）**：`SEVEN_DAYS_AWARDS`（sevendays 签到，与回归七日是两套 7 日）、`GET_SPRING_SEVEN_DAY_DATA`/`SPRING_SEVEN_DAYS_AWARDS`/`RECEIVE_SPRING_ACC_REWARD`（新春窗口 2026-08 已过期 + 依赖 active_signup/constant_reward 口径）
- 产出：仅 Return_SevenDay 7 份奖励（每天一次，7 天封顶）→ 防刷天然合规。

### 档 B（档 A + 任务/活跃度自定完成）
- 任务自定"按回归天数解锁完成"（如第 N 天完成第 N 个任务）→ 11 份任务奖励 + liveness 累计 → 5 档活跃度奖励可领。
- 产出 11+5 份奖励；完成条件是我们自定的（申报追认），有总上限（回归期内一次性）。

### 档 C（只做门 + 拉取键，领取全拒）
- 仅 GET_RETURN_SEVEN_DAY_DATA / GET_RETURN_TASK_DATA / GET_RETURN_GIFT / REFRESH_RETURN_GIFT_AWARD；RETURN_SEVEN_DAYS_AWARDS 也拒 → 面板能开但零产出。
