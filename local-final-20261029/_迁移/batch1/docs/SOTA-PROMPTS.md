# SOTA 提问包（脱敏版）—— 拿指导，不交源码

> 用途：把"我们卡住的问题"变成**通用技术问题**去问外部模型，拿回可落地的架构指导。
> 原则：**A 档零暴露**（只问方法），**B 档低暴露**（贴脱敏伪代码，不贴原码）。
> 红线见文末 §D；答复能不能用见 §C。

---

## 0. 怎么用

1. 想清楚你卡的是「方法」还是「某一行代码」。
   - 方法 → 抄 §A 里的整段（含背景和约束，别只抄问题，模型缺上下文会瞎猜）。
   - 具体模块 → 按 §B 的规则改写 3–5 个函数，再贴 §B2 模板。
2. 一次只问**一个**问题，别把四个问题塞一条消息。
3. 拿到答复先过 §C 的验收清单，不合格就追问"请给出可验证的断言/最小实验"，不要接受"看起来对"。

## A 档：四个零暴露问题（直接复制整段）

### A1 契约测试体系评审

```
背景：我在做一个"客户端↔服务端"协议的离线替代实现（客户端是 Cocos Creator 2.x 打包的
手游，HTTP 请求/响应式 RPC，没有公开文档，只能从客户端代码里反推契约）。我不改客户端，
只在自己的进程里拦截请求并生成应答。

现状数字：
- 客户端一共发出 812 个不同的动作（action）。
- 其中 509 个动作，客户端不读取应答里的任何字段（纯 ACK 即可）。
- 剩下 303 个动作会读应答字段（平均每个读 2–3 个字段，有嵌套路径）。
- 我已为这 303 个动作建立了"形状表"：每个动作一份 {字段名: 类型} 的期望，共 1105 个字段位。
- 进程内自检每次启动跑 1103 条断言：动作存在、eRet 值、字段齐全、类型正确。
- 另有 5 套独立回归（协议编解码 82 项、xhr 层 21 项、业务语义 20+ 项）。

我要什么：
1. 这套"形状表 + 进程内自检"作为契约测试体系，最大的结构性漏洞在哪？（我给的方向是"字段级契约"，但真正的事故都出在"语义级"：同一个字段在不同接口里含义/格式不同、空对象与缺失字段被同等对待、增量字段与全量字段混淆）
2. 请给出 3 类我应该补的测试（每类给一个具体断言写法，不要泛泛而谈）。
3. 如果只能加 20 条断言来拦"最贵的回归"（存档被清空、进度回退、数值凭空增加），你会加哪 20 条？

输出格式：先给结论（≤5 句），再给清单（每条一句话 + 一个断言示例），最后给"你可能做错的地方"。
```

### A2 服务端权威状态机分层

```
背景：单机离线场景。客户端是现成的（不能改），它把服务端当权威：进游戏时拉一次**全量快照**，
之后靠**增量变更表**（形如 note.xxxCh）更新本地；另有 3 个接口是"整份替换"语义
（列表/背包/任务），返回空就等于把玩家数据清空。

我现在的实现是"回放 + ACK"：维护一个 JSON 存档，收到请求就按客户端发来的值记账，
再按需回放快照。问题是没有真正的玩法状态机：
- 任务进度（打怪/采集计数）客户端只算显示，服务端没有计数器；
- 挂机/修炼的收益是按常量返回的，没有时间推进；
- 战斗是客户端算完结果来领奖，服务端只回一个固定模板。

我要什么：
1. 把"回放层"升级成"权威状态机"的分层方案：领域状态、事件、结算、快照/增量投射各自放哪一层？
2. 这类"客户端预演 + 服务端只记账"的系统，最容易产生哪几种状态歧义？给出防止歧义的通用规则。
3. 如果服务端状态只允许存一个 JSON 文件（设备上，无数据库），状态机的边界应该怎么划？

约束：单玩家、无网络、必须能随时降级回"回放层"（客户端不许崩）。
输出格式：分层图（文本即可）+ 每层职责一句话 + 3 条最容易踩的坑。
```

### A3 存档版本演进

```
背景：单机离线补丁，存档是一个 JSON 文件（当前 ~700 字节，未来预计 20–100 KB）。
字段结构还在快速变化（最近一周改了 5 次：新增装备实例表、技能改存三元组、
任务奖励名单）。用户数据不可接受丢失（这是玩家的全部进度），且**没有数据库**，
只有文件读写。

我要什么：
1. 存档版本化方案：用 saveVersion + 顺序迁移函数，还是用"读时补默认值"？两者能否混用？
2. 如何在开发期就拦住"改字段把老档写坏"？（我要的是能在 CI 里跑的断言，不是流程建议）
3. 自动备份策略：什么时候备份、保留几份、如何检测"写坏了"并自动回滚？

输出格式：给出迁移函数签名 + 一个 CI 断言示例 + 备份策略表（时机/份数/回滚触发条件）。
```

### A4 冷启动等待隐藏

```
背景：客户端冷启动到可交互约 16 秒（Cocos Creator 2.x，本地资源，无下载）。
我们在客户端进程内注入了一层应答器（拦截网络请求），所以"服务端侧"其实是本地计算，
几乎不耗时。16 秒主要花在引擎初始化、资源解析、首屏 UI。

我要什么：
1. 在不改客户端的前提下（只能从外部注入/拦截），有哪些手段能把这段等待"藏起来"或缩短？
   请区分：真优化（缩短总时长）vs 观感优化（减少焦虑）。
2. 哪些手段风险高（比如提前触发 UI、跳过初始化步骤），我不该碰？
3. 给一个"先测再改"的测量方案：怎么确认那 16 秒到底花在哪几段？

输出格式：按"真优化/观感优化/别碰"三栏给清单，每条标风险等级（低/中/高）。
```

### B0 脱敏规则（七条，逐条执行）

| # | 规则 | 例子 |
|---|---|---|
| 1 | **改名**：业务名词换成角色名（Skill→Ability、门派→Faction、潜能→XP） | `upgradeSkill` → `upgradeAbility` |
| 2 | **去 ID**：所有数字表 id、物品 id、任务 id、NPC id 换成 `ID_A` / `N` | `skillArr:[15,0,1]` → `[targetLevel, progress, tier]` |
| 3 | **去字符串**：语言表 key、资源路径、UI 预置体名、接口域名、密钥一律删 | `storeUI/AlchemyFurnace` → `UI_PANEL_X` |
| 4 | **去注释原文**：注释改写成你自己的话（它们是他们的表达） | 中文注释全部重写 |
| 5 | **保留结构**：控制流、分支条件、数据形状、参数个数与顺序**必须保留**（这是分析价值所在） | `if (a.pgr >= cost) {...} else {...}` 原样保留 |
| 6 | **标注"实测语义"**：凡是你在真机验证过的字段含义，用 `# 实测:` 写在旁边 | `progress  # 实测：原始累积值，不是百分比` |
| 7 | **一次一个模块**：≤120 行，只留被问的那条路径，删掉无关分支 | |

### B1 示例：技能升级模块（已脱敏，可直接贴）

```
这是客户端（Cocos Creator 2.x）里"学技能"这条路径的伪代码，已脱敏。
数据形状：回合制手游里的"能力等级 + 升级进度 + 突破等级"。

# ---- 客户端 UI（面板） ----
onClickLearn(item):
    model = SkillTable.getItem(item.id)        # 客户端自己的模型
    cost  = xpCostForLevel(model.level)         # 每级需要的经验
    if model.progress >= cost:
        send(UPGRADE, { targetLevel: model.level + 1,
                        progress: model.progress - cost,
                        tier: model.tier })
    else:
        enterLearningMode()                     # 停止按钮可点，攒经验期间不可再学
        pendingItem = item                      # 面板本地预演：显示 targetLevel = level+1

onClickCancel():                                # 用户点"取消"
    exitLearningMode()
    send(UPGRADE, { targetLevel: pendingItem.targetLevel,
                    progress: pendingItem.progress,
                    tier: pendingItem.tier })   # 注意：取消也是发同一个 UPGRADE

# ---- 客户端响应处理 ----
onUpgradeResponse(res):
    showToastIf(res.returnPro)                  # 只读 eRet 和 returnPro
    refreshPanelFromModel()                     # 面板不读应答里的等级

# ---- 我实现的服务端（离线替代） ----
onUpgrade(req):
    cur = ledger[req.id] or {level: 0, progress: 0, tier: 1}
    if req.targetLevel > cur.level:
        gained = req.targetLevel - cur.level
        ledger[req.id] = { level: req.targetLevel,
                           progress: req.progress,      # 实测：客户端扣过本级消耗后的余值
                           tier: req.tier }
        ledger.xp -= COST_PER_LEVEL * gained
    else:
        # 取消 / 重复请求：等级不动，但进度必须落账，否则面板的 (80%) 会丢
        ledger[req.id] = { level: cur.level,
                           progress: req.progress,
                           tier: req.tier }
    reply({ eRet: 1, returnPro: 0,
            note: { change: { [req.id]: [level, progress, tier] } } })
```

   （已知：取消=目标≤当前；进度是原始值；等级只增不减）
2. 如果客户端模型与服务端账本出现偏离（客户端显示 5、账本 19），我应该以谁为准、如何自动收敛？

## C 验收：怎么判断它的答复能不能用

| 检查项 | 不合格的信号 | 处理 |
|---|---|---|
| 有没有**可验证断言** | 只说"应该注意…""建议考虑…" | 追问："把它写成一条能在 CI 里跑的断言" |
| 有没有**列假设** | 直接给结论、不提前提 | 追问："你这条建议依赖哪些假设？哪个假设不成立就失效？" |
| 有没有**指出现有做法的反例** | 全是附和 | 追问："我这套做法在什么情况下会错？给一个具体场景" |
| 有没有**编造事实** | 出现具体数字/字段名/接口名（它不可能知道） | 整段作废，只保留方法论部分 |
| 能不能**正交于实现** | 建议要求改客户端 | 本项目前提是客户端零改动，这类建议一律不采 |

## D 绝对不能贴的清单

- 任何密钥/IV/加密常量。
- 真实的接口域名、路径、服务器标识。
- 游戏/公司/角色名，以及任何能反查到作品的字符串。
- 配置表原始行（物品名、任务文本、语言表 id）。
- 他们代码里的中文注释原文（那是他们的表达，不是你的）。
- 完整的 bundle（哪怕一次）；一次最多一个函数级片段。
