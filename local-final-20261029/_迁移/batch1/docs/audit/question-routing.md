# 提问路由规则（2026-10-23 用户裁定）

> 出处：用户原话——「你最好把对我的问题转化为对顾问的问题，因为大模型倾向于满足我，即使我的想法不切实际你也会想方设法满足我，尽管这对于项目无益」。
> 这条是**流程规则**，不是一次性提醒。以后每一批材料都必须按它写。

---

## 1. 规则

把"我该怎么做"和"能不能动你的东西"**拆开走两条线**：

| 类别 | 判据 | 归谁 | 形式 |
|---|---|---|---|
| **判断类** | 任何"该不该做 / 哪种做法对 / 这个判据成立吗 / 顺序对不对 / 值不值得" | **顾问（SOTA R 系列）** | 写成封闭问题，进 outbox §五，编号进输出格式 |
| **许可类** | 只涉及"动用户的资产/文档"：消耗道具、改存档、改交接文档、改设备文件 | **用户** | 一句话问，只要"可以/不可以"，**不许夹带判断** |

**禁止**把判断类问题包装成许可类（例："要不要用掉这本书做实测？"——这里"要不要"是判断，"用掉"才是许可）。
正确写法：先问顾问"实测是否必要、最小可判集是什么"，顾问判"必要"之后再问用户"允许用掉这件道具吗"。

## 2. 为什么

1. **主模型有附和偏差**：用户说 A，主模型倾向论证 A 可行；用户问"要不要做 X"，主模型倾向说要做。把判断交给用户 = 让偏差直接进决策。
2. **顾问有制度性对立面**：`outbox/00-INSTRUCTION.txt` 的五条规则要求它给条件、给反例、给失效前提，且被明确允许说"材料未提供"。它的附和成本比主模型高。
3. **用户的权力是许可，不是技术裁定**：用户不需要（也不应该被迫）在"哪个字段该回什么"上做判断。

## 3. 落地形式（每批材料必须带）

在 outbox 每封回执里加两段：

```text
【五、我要你回答的 N 件事】
  > 编号 ①②③ 是技术判定；④ 是"我打算做的动作该不该做"——这一类也归你判，不归玩家判。
  > 玩家只保留一类权力：许可（动他的东西、动他的文档）。判断权在你这。

【六、给你的额外约束（必读）】
  1. 我对"自己想做的事"倾向于自我合理化：凡是**我主动提出的做法**，请按"先假定它不成立"来审。
  2. 我对你的结论也倾向于附和：请主动找我错，回答里至少一条是否定我的；若确实没有，必须明说并逐条给出查验依据。
  3. 不许给折中方案：判"不成立"就直接给替代路径或"材料未提供"。
  4. 单独回答：我会不会因为既往许可，把本该重新取得裁定的事当成已批？若是，列出必须重新取得用户裁定的动作清单。
```

## 4. 主审自己的执行检查（每批提交前逐条过）

- [ ] 我有没有在回复里问用户"要不要/哪种好/顺序对不对"？有 → 改写成给顾问的封闭问题。
- [ ] 我留给用户的问题，是不是**只有**许可类（动资产/动文档）？
- [ ] 我论证自己的方案时，有没有先写它的失效前提？
- [ ] 本批材料是否带上了 §六 的四条约束？
