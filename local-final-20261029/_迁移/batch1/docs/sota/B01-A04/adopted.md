## 四、无法调和 / 只能选一个（决定权在用户）

1. **自动补齐 vs 数值凭空增加**：离线版里采集物若没有别的合法来源，关闭补齐会让部分任务永远做不完；保留补齐就承认"凭空增加"。→ 建议：**改成"只在交任务时校验背包，接任务不再补"**，若因此卡任务，再单独给一个显式的 `TaskItemGrant` 维护动作（只在命令通道触发）。
2. **"一次击杀只推进一个任务" vs 客户端显示**：若客户端把一次击杀计入所有匹配任务，服务端只记一个就会造成"显示完成却交不了"。→ 必须先抓客户端行为。
3. **重复提交幂等 vs 没有战斗唯一身份**：若结算请求既无实例 id 也无 1:1 开战，二者不可兼得。→ 我们的 16:16 成对关系让"用开战序号做水位线"可行，前提是开战与结算严格一一对应（需验证）。
4. **509 个 ACK 动作被拒后客户端不可见**：自愈只能修存档，修不了玩家当时看到的界面。接受。
