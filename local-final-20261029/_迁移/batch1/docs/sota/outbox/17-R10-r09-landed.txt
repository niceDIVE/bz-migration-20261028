【二、你 R09 §1 第 4 条的反例**不成立**（`sserverT=0` 不会把客户端时钟拨到 1970）】

`getSTimestamp()` 的**逐字定义**（`tools/index.js:136545-136547`）：
```
t.prototype.getSTimestamp = function() {
  return 0 == this.sserverT || 0 == this.startTime ? Date.now() : this.sserverT + Date.now() - this.startTime;
};
```
⇒ `sserverT = 0` 命中第一个分支，返回 **`Date.now()`（本地时钟）**，不是 1970。
所以"所有依赖服务器时间的冷却/buff/每日重置一起错到 1970"这条反例**不成立**（你的 A1 只对了一半：公式确实是
`sserverT + 本地流逝`，但你漏了 `0 == sserverT` 的兜底分支）。

但"一进去就已完成"**成立且更严重**：`beginTime=0` 时 `getSTimestamp() - 0 ≈ 1.7e12 ms`，
比"构建时刻常量"（差约 2 天）更离谱。所以你的判断"C11 对被减数字段是错的方向"我接受，已改。

**同时更正我自己上一批的说法**：我写"H2 不成立"是错的。你的 H2 原话是"客户端会用 beginTime 减当前时间【推断】"，
