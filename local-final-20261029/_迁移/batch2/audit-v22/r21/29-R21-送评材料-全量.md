## 五、线协议与信封

- 请求体：`{mod:"User", do:"<Action>", p:{…}}` → LZString(Base64) → AES-256-CBC → Hex。
- Key / IV 为固定常量（**值已脱敏**；如需判算法强度，只需知道是 AES-256-CBC + 固定 Key/IV、无随机盐）。
- **信封按 URL 决定，不按动作**：入口服 `:9898` → `{MsgData}`；账号服/游戏服 → `{code:200, MsgData}`。少了 `code` 客户端**静默丢弃**。

## 七、`note` 五子表（本项目最易错的一层）

**机制**（`index.js:59325`）：

```js
if (g.p) {
  var I = g.p;                                          // 59324 协议名，如 "User.upgradeSkill"
  if (g[I].note) for (var E in g[I].note) f.MessageCenter.dispatch(E, g[I].note[E]);  // 59325
  f.MessageCenter.dispatch(I, b ? g : g[I]);            // 59332
}
```

⇒ **`note` 的键名本身就是 MessageCenter 事件名**；子表在协议应答**之前**派发；键名拼错不报错、只是没人听。
五个键即五个常量（`index.js:59569-59580`）：`INVENTORY_CHNG:"ivch"` / `ECONOMY_CHNG:"eco"` / `ATTR_CHANGE:"attrch"` / `EQ_CHNG:"eqch"` / `SKILL_CHANGE:"skch"`。

| 键 | 形态 | 客户端主消费点 | 写错的后果 |
|---|---|---|---|
| `ivch` | `{itemID: 绝对新数量}`，0=删除 | `index.js:64674`（赋值 `setItem(n,o[n])`） | 发变动量 → 数量被覆盖 → **能反复卖** |
| `eqch` | `{uid:[0]}` 删 / `{uid:[1,[type,num,(skin)]]}` 加 | `index.js:64678` | 形状错 → 装备不落地 |
| `eco` | 只认 6 键 `coins/ptt/gold/exp/chips/yuanbao`，全为绝对余额 | `index.js:64698` | 钱包不变；潜能键是 `ptt` 而非 `potential`，发错静默丢弃 |
