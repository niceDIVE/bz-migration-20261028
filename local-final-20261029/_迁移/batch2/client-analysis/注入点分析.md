## 1. 启动链路（main.js 实读，155 行全明文）

```
libcocos2djs.so (SpiderMonkey JSB)
  → assets/main.js                     ← 明文，可整读
      ① 把 getWritablePath()+"hotfix/" unshift 到搜索路径最前 (main.js:5-8)
      ② require('src/settings.js')     ← APK 内实际是加密的 settings.jsc
      ③ require('src/cocos2d-jsb.js')  ← APK 内实际是加密的 cocos2d-jsb.jsc
      ④ require('jsb-adapter/jsb-engine.js')  ← 明文 6000 行，已提取
      ⑤ window.boot():
          cc.assetManager.init({ bundleVers, remoteBundles, server })  ← server 来自 settings
          cc.assetManager.loadScript(settings.jsList.map(x => 'src/' + x))
          loadBundle(INTERNAL/RESOURCES/MAIN) → 加载 43 个业务 bundle (index.jsc)
```

## 2. 核心结论：hotfix 覆盖 = 进程内单机的钥匙

`main.js:5-8` 把 `hotfix/` **unshift 到搜索路径最前**（不是 append）——
同路径同名的文件，hotfix 目录里的**明文版本优先于 APK 内的加密版本**被 `require` 命中。
无需重签 APK、无需解密 jsc，把补丁文件放进客户端可写目录即可生效。

## 3. jsc 加密观察（当前路线无需破解）

- 43 个 `.jsc` 全部是业务 bundle 的 `index.jsc`（Cocos 3.x 打包格式）；
- `assets/src/` 仅两个加密文件：`settings.jsc`、`cocos2d-jsb.jsc`；
- 样本 `index.jsc` 头 4 字节 = `23 42 6E 44` = **`#BnD`** 自定义签名，对应 `libEncryptorP.so` 解密；
- 走 hotfix 明文覆盖路线可**完全绕开解密**；解密仅在未来需要改业务逻辑时才有意义。

## 4. 拟定注入方案（进程内自问自答，零网络）

> **路线更新（2026-10-21 实读 main.js 后修订）**：原计划的"明文 settings.js 覆盖"存在
> 鸡生蛋问题（settings 字段全集锁在 settings.jsc 里）。改为**前置 hook 进
> `jsb-adapter/jsb-engine.js`**——它在 APK 内本是明文（已完整提取），加载时机在
> `boot()` 之前，且 `main.js:14` 显示 `window._CCSettings` 是原生层解密好的明文对象，
> hook 运行时直接可读，**彻底绕开 jsc 解密**。

```
客户端可写目录/hotfix/
└── jsb-adapter/jsb-engine.js   ← 原版明文 + 前置 hook（构建产物，见 hotfix-patch\）
      1. dump window._CCSettings（server/jsList/launchScene 运行时明文）
      2. 探针：透明包装 XMLHttpRequest，记录游戏真实请求/响应形态
      3. 环回：XMLHttpRequest 整体替换 → {mod,do,p} 进程内分发
         （语义对齐 gateway\src\rpc.js，存档走 jsb.fileUtils JSON 快照）
      4. 广告/统计 SDK：游戏 JS 不再发起网络调用；Java 层 SDK 无 JS 触发源即静默
```
