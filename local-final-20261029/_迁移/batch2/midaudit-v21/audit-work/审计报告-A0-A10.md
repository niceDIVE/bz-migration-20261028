## A3 STUB 中性性判定规则

**判定规则（"中性"当且仅当以下全部成立）：**
- S1 不写存档、不发 note（stub.js 现已保证：saveAfter 原样返回，body 无 note）。
- S2 客户端对该应答的所有读取点，在"字段缺席"与"字段=兜底值"两种情况下**行为等价**。即：M2 读点 mode 为 hasOwnProperty/in（存在性读）→ 缺席=假，发 `[]`/`{}`=真，**不等价，必须不发**；mode 为属性读且客户端只做容器遍历（for-in/length 迭代）→ 空容器与缺席等价，可发。
- S3 eRet 值不触发下游服务端依赖流程：若 M2 显示该动作应答会驱使客户端继续发后续请求或等待服务端推送（如 eco 每次附派 SHOP_BUY_ITEM，M4:80），兜底"成功"会让流程空转——此类动作不得兜底成功。
- S4 required/shapes 非空禁兜底（已有，stub.js:30）；且"全量重建"判定不能只靠 overrides 的 required——M2 有 64689 形态（parseEq 进装备账本，M4:69）这类无 required 但回空即崩的消费点，应按字段名单禁兜底。
- S5 付费名单单一来源：stub.js 的 PAY_RE_DEFAULT 与 oracle.config.payActionRe 二选一，另一处引用之（现在两处独立维护，会漂移）。

**现有拦截漏掉的情形（全部有实证）：**
1. **真值翻转**（漏 S2 的存在性读）：heuristic 给 plain 字段猜 `[]`/`{}`。出货 stubs.json 实证：`"User.ChallengePVP": {"eRet":1,"AttckData":{},"EnemyData":{}}` → 客户端 `if (o.AttckData)` 为 **true**，进入本应无数据不进的分支（实测演示）。根因：M2 把 `if (o.x)` 记"属性读"（plain），而 switch 只认 hasOwnProperty（build-contracts.js:80）；stub.js:24 只跳 `spec.switch`。
2. **卡死/空转型**（漏 S3）：契约没有"后续推送依赖"概念；任何期望下文推送的动作被兜底 eRet:1 后客户端等一个永远不会来的事件。
3. **形状合法但语义致命**（漏 S4 后半）：无 required/shapes 的装备账本类动作，回空对象让 64689 的 parseEq 链崩——L1 不查（fields 空），L0 离线不跑。
4. **付费名单漂移**（漏 S5）：改 config 不改 stub.js 即漏拦。

## A10 反例（本审计方法自身会失效的场景）

1. **合成样例外推失效**：全部展开器反例在 1.1KB 合成文件上构造。真实 10 万+行压缩产物里 `.on(` 同行多事件、同名方法跨类碰撞（ast-expand.js:32-35 的最近行启发式）可能让闭合率与字段归属完全不同——我的反例证明"判据有洞"，不能证明"真包闭合率数字"。
2. **重构等价性**：第 4/13 步的沙箱重构与原 bash 管道在异常传播上有差（`set -euo pipefail` 会把 `grep` 无匹配、`head` 短读之类变成整体失败）——我逐条跑可能放过某步"在 bash 下其实会断"的路径。
3. **枚举不完备**：假 PASS 清单是我构造出复现的通道（6 个），"至少 3 个"是下界。例如 L4 的 volatileKeyRe/idKeyRe 白名单过宽、diff() 数组按位比较对乱序数组的误判，我未做成复现，只作【推断】记录在此。
4. **上游污染**：manifest 校验只证明包内一致；若 M1 的 send/on 列本身抄错（R21 材料错），我的 C7"成立"与 426 口径全部继承错误。W2 的 M1 复算只能证明 registry 忠实于 M1，不能证明 M1 忠实于客户端。
5. **材料阅读深度**：r21/R21-回执与 29-全量只抽了标题层（W2），M2 只核了统计节——若回执中有对某条 C 声称的前提修订（如某动作降级为 PUSH），我的 A1 判级可能引用了过期前提。
