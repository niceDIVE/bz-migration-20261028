## 3. ★ 一个必须提请你注意的白拿陷阱（我没照发）

`GetRandomEventAward`（REQ_WM_ADV_RWD）的请求是：
```js
// index.js:143865-143871
var o = { adventureID: t, award: e, eventID: c.RumorModel.eventID };
u.NewAdventureModel.isDeadMonster = !0;
p.NetMgr.http.sendRequest(n.HttpConst.REQ_WM_ADV_RWD, o);
```
**`award` 是客户端自己算出来传上来的数值。** 照它写进钱包 = "客户端说给多少就发多少"。

本工程没有按 `adventureID`/`eventID` 查的奖励表，所以我的实现是：**只回成功，一件东西不发**，
并把客户端自报的 `award` 打进日志。冒烟有一条专门灌 `award: 999999` 断言背包不变。

发奖政策我按唯一判据执行：**奖励源必须是服务端表，键必须服务端可校验**。
所以 19 个里只有两个肉鸽结算（reqKeys 里有 `npcID`）接了 `BZ_NPCDROP`，与既有 `CheckBattleResult` 完全同口径。
