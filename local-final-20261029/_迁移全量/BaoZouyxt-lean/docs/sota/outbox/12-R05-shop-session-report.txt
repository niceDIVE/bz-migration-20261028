【二、本轮修好的 6 个实测故障（全部有源码依据 + 活进程证据）】

F1 用消耗品后崩溃（"秘籍白吃"）
- 现象：用掉秘籍（3626）→ 客户端 `TypeError: Cannot read property 'name' of null @ index.jsc:64796`；物品已消耗、效果未生效。
- 真因：形状表给 `useItem` 补了 `formulaID:0` 等"分支选择器"字段；客户端用 `hasOwnProperty("formulaID")`
  当开关 → `getItem(0,"formula")` 得 null → `n.getText(y.name)` 崩。
- **更隐蔽的一层**：旧修复在 handler 里删字段，但 `dispatch` 是"先 handler、后 `fillShape`"，
  `fillShape` 又把形状表里的字段补回来 → **修复从未生效**；而自检断言"形状字段必须在应答里"恰好因为补回来而永远绿。
- 修法：在**生成器**里剔除（`SHAPE_OMIT`），handler 删除只作防御；新增回归用例（必须加载形状表才能复现该路径）。
- 判据：凡"`hasOwnProperty` 当开关"的字段，缺省一律不发。

F2 食物不加饱食度
- 真因：客户端**不做本地应用**——请求带 `hg`=当前剩余（index.js:65302），只有应答 `note.attrch.hunger`
  才会落地（59325 逐键 dispatch → 59571 `ATTR_CHANGE="attrch"` → 142440-142441 直接赋值）。
  我们以前只回 `note.ivch/skch/eqch`。
- 修法：生成 `BZ_ITEMEAT`（Type==2 && Effect==1 → Data1，66 种）；`useItem` 回
  `note.attrch.hunger = hg + Data1×数量`（无 `hg` 不发、不瞎猜）。

F3 裁缝铺点页签卡死（客户端崩溃，用户实测）
- 真因：`User.GetFashionList` 只有"形状应答"，缺 `type`/`FashionArr` →
  `FashionShopNewUI.showItem` 不执行（scripts2:21436-21437）→ `curSelectType` 未初始化 →
  点页签 `btns[undefined].getChildByName` 崩（21830）→ UI 死掉。
- 修法：真 handler 回 `{eRet:1, type:回声, FashionArr:[[物品id,0]×266]}`（`BZ_FASHION`=fashionall 266 行）。

F4 伙伴界面每帧崩（日志刷屏，拖性能）
- 真因：`getFriendPartner` 形状应答缺 `notFriendPartnerData` → `lockFriendData=undefined`（scripts3:58456）
  → `checkTaskFinishState` 每帧 `hasOwnProperty of undefined`（59334）。
- 修法：真 handler 回 `notFriendPartnerData:{}, friendPartnerDatas:{}, isUnlock:0, happinessNum:0`。

F5 成就面板空白（用户实测）
- 真因：`checkGroupOpen = gPoints.hasOwnProperty(组id)`（scripts3:3045）；空 `groupPoints` → 零组 → 零条目。
- 修法：`groupPoints` 补全 19 个组 id（`BZ_ACHIEVE_GROUPS`=achieve_group 19 行），值 0。

F6 活动面板"内容空"
- 真因两层：①`getActivityState` 的 1001/1002 tab 判据在 `RoleOtherInfo.activeObj`（来自 LoadGame 的
  `activityArrFlag`）；②`getActivityCounts.dataArr` 回了对象 `{}`，而 `DailyMissionUI.start` 把它当
  **标量数组**（`dataArr.length` 循环）→ 0 行。
- 修法：`activityArrFlag=[0,0]` + `dataArr=[0×18]`（18=daily_active_tips 行数）+
  `activityShows=[0,0]`（关掉含付费入口的 1003/1004 tab）。
