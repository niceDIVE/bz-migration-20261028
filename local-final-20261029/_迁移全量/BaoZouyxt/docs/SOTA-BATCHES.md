# SOTA 协作方案：A 档当基底，B 档分批投喂

> 目标：外部模型的产出必须**落成我们项目的规格与断言**，否则不进仓库。
> 上位文件：[SOTA-PROMPTS.md](SOTA-PROMPTS.md)（提问包 + 脱敏规则 + 验收清单 + 红线）
> 本文件管：**怎么分批、每批要什么、答复怎么落地、台账怎么记**。

---

## 一、A 档 = 项目基底（答复直接变成四份规格文件）

A 档的四个问题不是"参考意见"，而是**先于所有 B 批的验收依据**。每问完一个，把答复里能站住的部分写成下面这份文件，之后所有代码改动都要能对着它自检。

| A 问题 | 落成文件 | 里面必须有什么 | 谁验 |
|---|---|---|---|
| A1 契约测试体系 | `docs/CONTRACT-TESTS.md` | 断言清单（含"20 条最贵回归"）、每条的触发条件、现有 1103 项自检的缺口 | 本地：`node test\*` 必须全绿且新断言能重现至少一个历史 bug |
| A2 权威状态机分层 | `docs/STATE-MACHINE.md` | 分层图、各层职责、跨层调用禁令、状态歧义的通用规则 | 本地：契约测试按层挂载；回放层可随时降级 |
| A3 存档版本演进 | `docs/SAVE-VERSIONING.md` | `saveVersion` + 迁移函数签名、CI 断言、备份与自动回滚策略 | 本地：拿历史存档快照（我们已存了 4 份）逐个跑迁移，必须全通过 |
| A4 冷启动 | `docs/COLDSTART.md` | 测量分段方案、"别碰"清单、风险等级 | 本地：`run.ps1 smoke` 前后对比总时长 |

**纪律**：这四份文件写不出"可验证断言"的段落，就退回给外部模型追问（"把它写成一条能在 CI 里跑的断言"），不落文件。

## 二、B 档分批表（按玩家真实路径排序，先能玩下去）

每批的固定结构：**范围（函数级）→ 输入（脱敏伪代码）→ 问题（3 条以内）→ 交付物 → 本地验收 → 依赖**。

| 批次 | 模块 | 现在有什么 | 缺什么（要问的） | 本地验收 | 依赖 |
|---|---|---|---|---|---|
| **B01** | 任务进度状态机 | `acceptTask` 补 `SpRequire` 物品、`getFinishTaskAward` 发奖励、`done/rewarded` 防重发 | `Require` 里"杀 N 只/采 N 个/到某地"的计数该由谁算、怎么在只有 JSON 存档的情况下做增量与回放 | 打 3 只怪 → 任务进度 = 3；重启后仍 = 3 | A2 |
| **B02** | 挂机/修炼结算 | `OnCheckBreak` / `OnHookBreak` 只回常量 `finish:1 hg:100` | 时间推进的结算模型：客户端本地时间 vs 服务端时间、离线补算、防刷 | 挂 10 分钟 = 预期收益；改系统时间不产生收益 | A2、A3 |
| **B03** | 战斗奖励 | `killNpc` / `CheckBattleResult` 只回模板 | 按战斗结果 + 掉落表发奖；连击/多怪结算；保底与上限 | 打 10 只 → 掉落符合表；无重复发奖 | B01、内容表装载器 |
| **B04** | 商店 | `buyShopItem` / `QuickBuyItem` 已记账 | 价格表、限购计数、每日刷新、货币优先级 | 买 3 次超限 → 拒绝且不扣钱 | A3 |
| **B05** | 物品效果 | `useItem` 回 `note` 五个变更表（形状对） | 按物品效果真发：加属性/加技能/召唤/任务道具，各自往哪个变更表写 | 用 5 种不同效果物品 → 五表分别正确 | B04 |
| **B06** | 装备属性 | `PutOnEquipment` 记账 `[type,itemID]` | 属性计算、强化等级、宝石/水晶、换装后的属性回放 | 穿 3 件 → 面板属性 = 表算值 | B05 |
| **B07** | 门派 | `joinSchool` / `CheckOutSchool` / `OutSchool` 已有 | 贡献、职位、师门任务、每日俸禄 | 入门 → 领俸禄 → 退门，账本自洽 | B01 |
| **B08** | 好友/排行/聊天 | `FriendList` / `rankList` 形状对 | 本地假数据生成策略（离线无其他玩家时的合理呈现） | 面板打得开、不崩、数据稳定 | — |
| **B09** | 钓鱼/棋盘/比武等小游戏 | 各有 handler，回常量 | 各自的结果判定与奖励 | 每个小游戏一轮完整流程 | B03 |
| **B10** | 活动/跨服/婚姻/子女 | 全部 ACK | 判定"离线不做"还是"做空壳但诚实" | 明确记录取舍，不出现"点了没反应" | — |

**批次纪律**

1. **一次最多 2 批在飞**（外部模型答复质量随上下文增长而下降，批越大越容易编）。
2. 每批输入 **≤120 行**脱敏伪代码，只留被问的那条路径。
3. 每批只问 **≤3 个问题**，每个问题必须能落到"改哪里/加什么断言"。
4. **答复一律当提案**：能编译进我们结构的才采纳，采信率低就换问法，不是换模型。

## 三、每批答复的统一输出模板（直接写进提问里）

```
请严格按这个格式回答：
1. 结论：≤5 句。
2. 断言清单：每条 = "当 X 时，系统必须 Y"，最多 8 条。
3. 边界清单：容易漏的边界条件，每条一句话（如 0、负数、重复请求、乱序、并发）。
4. 反例：我这套做法在什么场景下会错？给一个具体场景。
5. 假设：你这条建议依赖哪些前提？哪个前提不成立就失效。
6. 落地步骤：≤5 步，每步一句话。
```

**拒收信号**（出现任一条即退回重问）：只给"应该注意/建议考虑"而没有断言；给出具体字段名/数字（它不可能知道）；建议改客户端（本项目客户端零改动）；通篇附和我的实现。

## 四、台账（每批三件套，落在 `docs/sota/`）

```
docs/sota/
├── B01-任务进度/
│   ├── prompt.md      # 实际发出去的脱敏提问（含伪代码）
│   ├── answer.md      # 收到的答复原文（不改动）
│   └── adopted.md     # 我们采纳了什么：每条 → 对应断言/文件/提交
└── ...
```

- `adopted.md` 是**唯一有资格改变代码**的文件；没写进 `adopted.md` 的答复即视为未采纳。
- 每条采纳必须映射到至少一条断言或一个回归用例；映射不上的记为"参考，不入库"。
- 台账编号与批次表一致，方便以后回查"这个设计当初为什么这么定"。

## 五、跟本地流水线怎么配合（别互相踩）

| 活 | 归谁 | 理由 |
|---|---|---|
| 定位某个字段/函数的语义、查行号 | **本地苦力**（`gemini-3.8-flash-low`） | 要读 33 万行、要行号证据，本地最快最便宜 |
| 架构、分层、测试体系、版本迁移方案 | **外部 SOTA（A 档）** | 通用方法论，且不碰源码 |
| 单个模块的语义边界、边界条件穷举 | **外部 SOTA（B 档，脱敏）** | 结构能说清，且不泄露源码 |
| 真机验证、写回归、改代码、存档操作 | **主审（本 agent）** | 需要真机证据与写入授权 |

**一条硬规矩**：外部答复永远不能直接进仓库 —— 必须先过 §C 验收清单（[SOTA-PROMPTS.md](SOTA-PROMPTS.md)），再由主审改写成符合我们结构的代码 + 断言。
