## 三、送评协议（引用 `PROJECT-STATE.md` §1.2–§1.4，原文）

**SOTA 的输入条件**：看不到本仓 repo、不能执行命令、不能联网 → 每条结论所需的证据必须是材料里自带的行号或原文，材料必须自足、分卷。

**两步送评**：
1. 材料充分性预审——只送 §2 材料清单 + §3 状况 + §1.3 格式，问一句「要完成 D1–D6 还缺哪些材料？只列缺失项，不要开始评」。
2. 正式评估——按预审结果补齐材料后送全量。

**输出格式**（`PROJECT-STATE.md` §1.3 原文）：

```
按 6 段输出，不许增删小标题：
D1 目标与完成定义 / D2 架构分层 / D3 协议与状态 / D4 验证体系 / D5 工作量与路径 / D6 工作流程
每段必须包含：结论（带条件或可执行形式）、判据（怎么验证）、反例（什么场景下此结论失效）、材料缺失（缺什么就无法判断）
禁止：折中方案、"建议进一步评估"、"建议增加测试"、无行号的断言
允许：说"材料未提供"、说"这条判不了，因为缺 X"
```
