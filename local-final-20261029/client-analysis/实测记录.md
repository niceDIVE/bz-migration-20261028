## 攻克的三个致命 bug（按顺序）

1. **响应信封差异**：入口服 `:9898` 回 `{"MsgData":..}`；账号/游戏服 `bzgf` 800/900 回
   **`{"code":200,"MsgData":..}`**。少了 `code` 客户端静默丢弃 → 已按 URL 区分。
2. **假 XHR 事件契约**：客户端用 `xhr.onreadystatechange = fn` 赋值式监听，而假 XHR 只实现了
   `addEventListener` → 事件永不触发 → 客户端收不到任何响应。已兼容 `onxxx` 属性式监听。
3. **SDK 登录门**：静默 visitor 登录不通知游戏 JS。通过 dex 锚点 + 运行时探针定位到
   `LoginMgr.androidPlatformLogin` / `SvrSelectView.setServer/onEnterGame`，脚本化合成登录。

## 新增关键能力：命令通道（bz-offline-hook 内置）

## 重大发现：登录门的 JSB 桥（dex 静态分析，classes3.dex = 渠道 SDK）

```
SDK 登录成功后 evaluateJavascript:
  "javascript:if(!!window.JsBridge&&JsBridge.callback(<payload>))"
```

- **`window.JsBridge.callback` 是登录结果传回游戏 JS 的唯一桥**；
- 游客登录存在：`com/tfy/sdk/game/activity/Visitor_Activity`（UI 上被隐藏，back 箭头无入口）；
- 渠道校验端点：`bbs.maple-game.com/pe/login/validateLogin?userAccount=...`；
- **离线绕过方案（无需 Frida/无需解密/无需重签）**：hotfix hook（先于游戏代码运行）接管
  `window.JsBridge` —— 探针模式捕获真实 payload，环回模式直接合成登录成功，跳过渠道登录。
- hook v2 已实现 `JsBridge` getter/setter 垫片（225KB 构建通过，7 组单测全绿），待 VM 重启部署。
