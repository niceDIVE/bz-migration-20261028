【角色】
你是一位负责"离线服务端/游戏后端状态机"的资深架构师。材料是脱敏后的技术描述，不含商业信息。请只回答我列出的四件事。

【背景】
我做的是一个"单机离线"场景：客户端是现成的（Cocos Creator 2.x 打包的手游，HTTP 请求/应答式 RPC），
我不能改客户端，只能在自己的进程里拦截它的请求并生成应答。玩家的全部进度存在一个 JSON 文件里（约 1–100 KB），
没有数据库，进程随时可能被杀。

客户端把服务端当权威，遵循两条约定：
1. 进游戏时拉一次「全量快照」，之后靠「增量变更表」更新本地（形如 note.someChange: {id: [值...]}）。
2. 有 3 个接口是「整份替换」语义（背包、任务、好友列表）：返回空对象就等于把玩家数据清空。

我现在的实现叫「回放 + ACK 层」，形态是这样：
- 收到请求 → 按客户端发来的值记账（例如「穿装备」就记 slot→uid，「学技能」就把等级改成客户端要求的目标等级）
- 应答时把账本投射成客户端期望的形状
- 不知道语义的动作一律回一个"字段齐全但内容为空"的应答（保证客户端不崩）

结果是：**能点、不崩、能存档，但没有玩法**。具体症状：
- 任务进度（"杀 N 只怪""采 N 个东西"）没有计数器，只按"任务要求携带的物品"放行；
- 挂机/修炼的收益是按常量返回的，没有时间推进、没有离线补算；
- 战斗是客户端自己算完结果来"领奖"，服务端只回一个固定模板；
- 商店没有价格表/限购/每日刷新。

【约束】
1. 只有一个 JSON 存档文件，单线程，随时可能被杀进程。
2. 任何改动都必须能**随时降级回现在的「回放 + ACK 层」**（客户端一行不改，不能出现"某动作没实现就崩"）。
3. 写档必须走我们已经定下的一条链：迁移 → 校验 → 写后回读校验（因为平台没有 fsync）。
4. 数值和内容来自本地配置表（物品/任务/掉落/常量），表是可读的 JSON 数组，主键是 ID 列。
5. 单人，无联网，不考虑反作弊（但**不能出现数值凭空增加**，比如重复发奖）。

【我要你回答的四件事】
1. 分层：把「回放 + ACK 层」升级成「权威状态机」，请给出分层图（文本即可）与每层一句话职责。
   需要覆盖：领域状态、事件、结算、快照/增量投射、以及"未实现动作"的降级路径。
2. 状态歧义：这类"客户端先本地预演、再发请求、服务端只记账"的系统，最容易产生哪几种状态歧义？
   给一份"防歧义通用规则"（例如谁是权威、冲突时以谁为准、如何自愈收敛）。
3. 单文件边界：只允许一个 JSON 文件存状态时，状态机的边界应该怎么划？
   什么东西必须进状态机、什么东西只能算派生（每次重算），给判别标准。
4. 测试：给 5 条针对状态机的断言（要能直接翻译成代码），专门拦"状态漂移/重复结算/进度回退"。

【回答格式（严格照这个来）】
1. 分层图（文本）+ 每层职责一句话。
2. 层间调用规则：允许/禁止的跨层调用（≤6 条）。
3. 防歧义规则（≤8 条，每条一句话 + 一个反例场景）。
4. 状态机边界判别标准（≤5 条）。
5. 降级路径：当某动作没有实现时，怎么保证"不崩且不写坏状态"（≤5 句）。
6. 5 条断言（每条：断言 + 触发场景）。
7. 边界清单：最容易漏的边界（≤8 条）。
8. 反例：我这套「回放 + ACK」在什么具体场景下会产生不可逆的状态损坏？
9. 假设：你的建议依赖哪些前提？哪个前提不成立就失效。
10. 落地步骤：≤6 步，每步一句话。

不要给"建议引入事件溯源/领域驱动设计"这种只给名词的回答；每个名词后面必须跟"在我们这个约束下具体怎么做"。
不要假设我可以改客户端、可以加数据库、可以联网。
