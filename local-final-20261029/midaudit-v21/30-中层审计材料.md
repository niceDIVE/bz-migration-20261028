# 中层审计：裁判与提效工具包 bz-oracle v2.1

## 0. 这一轮审什么（范围）

R21 定下了路线（S0–S9）和六层裁判（L0–L5）。之后我做出一套可运行的工具包 `bz-oracle/`，包含裁判本体和 forge 提效工具箱，共 17 步自检，全部通过。

**这一轮审的是"中层"**：不重新讨论路线该不该这么走（那是上层，已在 R21 定稿）；也不逐行挑代码风格（那是下层）。只审一件事——**每个工具声称的能力，在代码里是否真的成立；以及它会不会给出"假 PASS"**，也就是有错却放行。

一个工具若会产生假 PASS，比没有这个工具更糟，因为它会把错误批量地放进后续的 GEN 流水线。

## 1. 环境与复现

- 运行时：Node ≥ 18（本机用 v22.23.3 实测）、bash、python3（只在解压时用）。不需要联网，依赖已随包放在 `bz-oracle/forge/node_modules`。
- 一键自检：
  ```bash
  cd bz-oracle && bash scripts/selftest.sh     # 预期最后一行为“全部通过”，共 17 步
  ```
- 包内同时附有 R21 材料（`r21/`：M1–M4、全量送评材料、R21 回执），作为契约与语义的依据。
- 自检用的全部是**合成样例**：一个合成的客户端片段、一份合成存档、合成数据表（`fixtures/`）。真实客户端三包、442 张表、真实 `bz-rpc-server.js` **不在包内**，原因是材料未提供。

## 3. 已知局限（已登记，不必再报；但如果你认为登记的理由不成立，可以反驳）

1. 装备出售守恒式缺失（变异 M09 存活），原因是装备出售价的规则表尚未取证。
2. 设备探针的真实符号未填，C4 只在模拟环境中验证过。
3. `replay/adapters/bz-rpc-server.template.js` 仍是模板，真实 handler 的分发签名材料未提供。
4. 投射器的 `attrSaveMap` 默认只投射 hunger 一项。
5. 请求参数抽取器（C12）仍是正则加括号配对；只有 C11 换成了 AST。
6. 吞吐数据来自演示生成器，不能用来估算周期。
7. HAR 的线格式是按三种常见形态容错实现的【推断】，原服的真实请求格式材料未提供。
8. 设备构建（995,676 B，md5 494862c8…）与仓库构建（998,966 B，md5 efcb0322…）不一致，S0 尚未闭合。

## 4. 审计方法要求

- 每条"假 PASS"必须附上**可执行的复现**：一个改动后的 fixture，或一个注入的 bug，加一条命令，以及运行后的实际输出。只有思路、没有复现的，算作【推断】。
- 修复建议要落到 `文件:函数` 级别，并给出可以加进 selftest 的断言。
- 判定"代码与声称是否一致"时，以**代码行为**为准；README 写了但代码里没有的，记作不一致。

## 5. 我要你回答的 8 件事

1. 逐条核对第 2 节 C1–C17 的声称：哪些成立，哪些部分成立，哪些不成立。每条都要给出证据（文件:行号或命令）。
2. 找出能让裁判（L1/L5、C16 离线 L2、C10 fuzz）**放过错误 handler** 的具体变异或 handler，至少 3 个，每个都附复现。按危害排序：会让 GEN 批量出错的排在前面。
3. C8 兜底 STUB 的"中性应答"在什么条件下不中性（会让客户端卡死、误显示奖励、或写坏本地状态）？给出判定规则，并说明 `gen-stubs.js` 里现有的拦截条件漏掉了哪些情形。
4. C11 AST 展开器在什么写法下会**误判为闭合**（漏字段却报 closed），或者在什么写法下会多收字段？给出至少 3 段 ES5 反例代码，以及预期的正确结果。
5. C16 客户端模型（client-model.js）与 M4 语义有哪些不一致？逐条对照 M4 的行号。"离线 L2 一致"能否替代真机 L2？如果不能，缺的是哪一部分？
6. C14 夜间循环把 LLM 输出接进来时，有哪些路径能绕过裁判（例如生成的代码改写存档以外的状态、读写文件系统、跳过 projector、篡改 rules）？给出沙箱或静态检查规则，以可执行形式写出。
7. 第 3 节已知局限中，哪几条**必须**在扩大 GEN 批量之前解决，哪几条可以并行解决？给出顺序和判据，判据要写成"当 X 时可以开始 Y"的形式。
8. 自检本身的可信度：17 步里，哪些步骤是"自己出题自己答"（测试数据与实现同源，或者预期值本来就是由实现生成的）？分别该如何改成独立判据？
